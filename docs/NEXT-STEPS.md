# 下一阶段建议（2026-10-20）

这份排序基于当前代码和使用流程，属于产品建议。PWA、虚拟文件树和 mDNS 已提供基础能力；下列条目仍是后续工作，不因写入文档而视为已实现。

| 优先级 | 方向 | 具体可交付内容 | 为什么值得做 |
|---|---|---|---|
| 最先 | 备份与恢复 | 整仓定时快照、附件与配置一起备份、恢复前预览、真实恢复演练 | 现有单篇历史与回收站能救部分误操作，整仓恢复才能覆盖磁盘故障和大批量损坏 |
| 最先 | 同步可见性与设备管理 | 展示待上传 / 待下载、首次合并预览、冲突对比、已配对设备列表与撤销 | 用户需要知道当前版本在哪台设备、失败后如何处理，不能只看到“同步完成” |
| 最先 | 浏览器访问与配对边界 | Web 服务登录、仓库范围约束、配对尝试限速、临时授权、加密引导 | PWA 会让仓库服务进入日常局域网使用，主应用 API 的访问控制应成为明确产品能力 |
| 随后 | 真正离线的移动仓库 | IndexedDB 笔记 / 附件存储、离线浏览、待同步队列、重连冲突处理、存储空间管理 | 目前 PWA 连接电脑服务，离线仅保留未保存文字；要出门独立使用，必须补数据层 |
| 随后 | 搜索与知识组织 | 中文分词 / 拼音、标题优先、按路径 / 标签过滤、保存搜索、模板与日记 | 比继续增加装饰效果更直接地改善“找得到、记得快” |
| 随后 | 编辑与移动真机手感 | Android / iOS 中文输入、软键盘、选区工具栏、表格 / 代码 / 引用的连续编辑、附件导入 | 自动化模拟覆盖不了所有输入法和系统行为，长时间写作的稳定性比功能数量更关键 |
| 持续 | 更大规模性能 | 全文倒排索引、正文按需加载、图谱布局放到 Worker / 更合适算法、启动 / 保存性能预算 | 文件树一万篇已验证，全文正文内存与全图力导向仍会随规模增长 |
| 持续 | 发布与兼容性 | 固定跨平台回归、崩溃日志导出、升级 / 回滚验证、变更说明、安装包与更新校验 | 让每次更新可放心安装，也方便定位用户机器上的问题 |
| 可选增长 | 数据带走与分享 | Markdown + 附件完整导出、导入检查、静态数字花园、链接修复报告 | 用户更容易信任随时能完整带走的数据；分享也能扩大实际用途 |
| 更后 | 插件与多人协作 | 先定义稳定扩展点，再评估插件隔离、实时协作和权限 | 这两类功能会显著扩大维护面，宜等编辑、保存、恢复和同步稳固后再展开 |

建议下一项先做「整仓备份与恢复」，然后补「同步状态 / 已配对设备管理」，再做「完整离线移动仓库」。mDNS 主要降低连接门槛，数据可恢复和跨设备状态清晰更直接决定用户是否敢把主力笔记放进来。

如果暂时只在个人电脑离线使用，可以把 Web 登录和移动离线库后移，优先做备份、搜索与编辑手感；如果主要用电脑 + 手机，离线移动库、访问控制与同步管理应一起规划。
