# 开发与质量检查

开发和 CI 使用 Node.js 22.13 或更新的 22.x 版本；安装依赖使用 `npm ci`，工具版本由锁文件固定。

提交前运行：

```sh
npm run check
npm run test:ci
```

`check` 依次检查自有 JavaScript 语法、渐进类型和 lint。`test:ci` 在临时副本中运行索引、安全与编辑回归，包含千篇/万篇真实文件、CSP 攻击样例及故意错误的静态检查样例；原始笔记不会被用作测试仓库。浏览器路径可通过 `TRACERY_BROWSER` 指定。

## 检查范围

- 语法：`server`、`sync-server`、`electron`、`public/js`、`scripts`、`test`，递归检查，跳过供应商资源。
- `no-undef`、`no-unused-vars`：`server`、`electron`、`public/js`、`scripts`。服务端与前端使用各自的运行环境全局变量；未使用形参和异常参数不强制报错。
- `checkJs` 与 `no-floating-promises`：路径、请求来源、用户文件边界、历史、笔记存储、索引缓存、CSP、目录监听、子进程启动、双链路径、快捷键、重连按钮，以及 CodeMirror 补全入口。实际清单在 `tsconfig.json`、`tsconfig.cm.json` 和 `eslint.config.mjs`。

这是分阶段检查，不是全项目严格类型检查。CodeMirror 补全文件通过 `@ts-check` 显式加入，其他编辑器依赖仍保持原有 JavaScript；新增模块或修改相关异步流程时应逐步扩大清单，不能为通过检查随意加 `@ts-nocheck` 或关闭规则。

## CI

GitHub Actions 在推送 main/master、PR 和手动触发时运行两项检查：

- `Static checks and browser regressions`：Ubuntu、Node 22、静态检查及安全/编辑回归。
- `Windows startup and save lifecycle`：Windows 原生单实例、启动错误、PDF、保存退出及端到端流程。

工作流使用只读仓库权限、完整提交 SHA 固定官方 Actions，不持久化 Git 凭据。检查失败会让工作流失败，报告和日志保留 7 天；不构建、不上传安装包、不发布 Release。合并前是否强制通过检查由仓库分支保护决定，本次未更改强制 PR 或管理员绕过策略。

完整本机回归仍可运行 `npm run test:all`。长文性能探针有独立的 16ms 目标，受机器和浏览器调度影响，不纳入跨机器 CI 门禁；性能目标未达标必须如实记录，不能把功能回归通过写成性能已达标。

## 仓库索引缓存

原始 Markdown 文件始终是数据来源。`.tracery/index.json` 是版本化清单，最多引用 64 个固定分片 `index-00.json` 至 `index-63.json`；正文副本用于暖启动，不属于备份。小于 256 篇只用一片，小于 4,096 篇用 16 片，更大用 64 片，避免小库承担大量缓存文件的打开开销。单篇变更只重写所在分片，清单在分片写完后原子提交。保存请求排队期间合并为最新快照，不丢弃最后一次变更。

暖启动校验清单、分片哈希和原始文件的 mtime/ctime/大小；丢失或损坏的分片回退读取原笔记，清单损坏或旧格式则重建。缓存无法写入也可打开与搜索。分片更新可能暂时与旧清单不匹配，此时选择重建，不把缓存当成唯一正文。更换缓存版本会在首次打开时重新解析一次。

`node test/run-suite.mjs only index performance` 验证增量写入、合并请求、提交中断、损坏重建、搜索与排序一致、绘图库失效及未解析来源。测试记录字节量、文件写入次数和耗时；耗时只作为测量结果，不设跨机器的毫秒门槛。搜索继续保留中文单字、标点和英文子串匹配。

## 历史备份边界

设置 → 通用的历史导出包含当前仓库的 v2 历史及来源未验证的旧版历史，不包含当前笔记或附件。导入只补充版本：相对路径和当前磁盘正文 SHA256 均匹配才关联 v2 历史；跨根目录需显式确认，正文已变或笔记已删除则报告跳过。旧版历史始终只可预览，不转为可直接恢复的 v2。冲突不覆盖现有记录，并回滚本次已添加的版本。

当前 JSON 备份上限为 32 MiB / 5 万版本；大于上限会明确报错，不静默截断。需要完整或大体积备份时，退出应用并分别保存仓库文件夹和用户数据目录的 history-v2、history。Windows 桌面版通常位于 `%APPDATA%/tracery`，自定义 `TRACERY_HOME` 时以该目录为准，源码默认项目根目录。历史自动快照仍保留每篇最近 20 个版本，长期保留应保存导出文件。历史备份是明文旧正文，不包含同步密钥和其他设置。

## 测试产物保留

`npm run clean` 默认只输出清理预览，列出绝对路径、大小和保留原因。确认后使用 `npm run clean -- --apply`；工具只删除旧测试的 work 副本，保留报告、日志、截图与已有源码身份。最近五次运行、首个失败、尚未解决的失败、各专项最终通过和含 `.keep` 文件的运行均保留。目录链接、越界或不完整报告会被跳过；发布目录全部保留，不自动清理。

失败运行默认保留完整副本，不能仅凭后续复跑通过就当作已定位。确认原因后，可在运行目录内写入 `.resolved` 文件说明结论；它仍需满足其他保留规则才会进入候选。测试报告记录源码提交及是否存在未提交修改；旧报告没有的身份信息不补猜。运行器结束时输出本轮磁盘占用。清理只处理受控的测试副本，不能替代笔记、历史或发布文件备份。

## CSP 边界

应用页面只加载同源脚本，importmap 按实际 HTML 的内容哈希允许；内联事件、普通内联脚本和 eval 均被阻止。同源 WebSocket 使用当前页面的实际主机和端口。样式保留内联支持，以兼容编辑器、绘图和现有自定义外观；笔记中的外链图片仍可加载。

仓库 JS、HTML 等活动附件按下载返回，并使用 `nosniff`，不能当作同源应用脚本。SVG 保留图片能力但禁止脚本执行。CSP 是额外防线，不能代替文本转义、路径检查或手机会话授权；手机 HTTP 仍仅适用于可信局域网。

规则依据：[W3C CSP](https://www.w3.org/TR/CSP/)、[TypeScript checkJs](https://www.typescriptlang.org/tsconfig/checkJs.html)、[未处理 Promise 检查](https://typescript-eslint.io/rules/no-floating-promises/)、[GitHub Actions 安全建议](https://docs.github.com/en/actions/reference/security/secure-use)。

## 配置恢复、启动与退出

全局配置、仓库同步配置和回收站索引通过同目录临时文件、文件 fsync 和替换提交，并保留上一份有效的 `.bak`。损坏 JSON 或不合法的全局配置结构先保存 `.corrupt-<内容摘要>`，然后尝试备份和旧配置；重复读取同一份损坏数据不重复生成证据。全局恢复来源在日志及本机启动提示中显示。无法读取、保留损坏证据或提交时报告错误；同步配置无法恢复时拒绝继续覆盖。文件替换和进程中断回归不代表所有系统、磁盘或真实断电场景都保证持久性。

回收站每项在移动之前保存恢复元数据，索引失败仍可列出已移动的项目。跨盘先完整复制到暂存位置，逐文件刷盘并回读比较 SHA-256，核对源目录清单和文件状态未改变，再公布目标、删除原件；副本损坏或源文件变化时保留原件，中断可能留下副本。旧流程遗留的未登记文件会标明原路径未知，恢复到仓库根目录。恢复遇同名继续另存，不覆盖现有文件。原笔记和历史仍使用各自的保存机制。

索引启动记录缓存失效原因、读取进度、笔记数量、复用/重建数和耗时；桌面先显示可关闭的启动状态窗口，完成身份握手后才打开编辑器。30 秒无响应超时随经过 nonce/PID 校验的进度重置，另有 5 分钟最长启动预算。关闭启动窗口可以取消。

桌面先完成前端保存确认，再通过 IPC 请求服务收尾；服务停止接受新请求并等待已接受的写入、同步及索引队列，关闭文件监听、自动任务、手机会话、LAN 发现、HTTP 与 WebSocket。CLI 支持 SIGINT/SIGTERM；Windows 桌面不依赖 kill 触发信号清理。服务收尾上限 15 秒，父进程等待最多 20 秒，失败会记录并兜底终止。

`node test/run-suite.mjs only storage-lifecycle startup close-lifecycle workspace-chrome` 验证磁盘/权限故障注入、真实进程中止、恢复与迁移、回收站事务、启动身份/进度/取消、退出时保存和明暗主题几何。`storage-lifecycle` 已加入 `test:ci`。

## 附件目标与笔记关联

`public/js/wiki-path.js` 的 `isAttachmentTarget` 统一常见显式附件后缀分类。附件不进入缺失笔记推断，也不追加 `.md`；编辑器通过附件入口打开，缺失附件只反馈找不到。普通笔记目标和笔记嵌入仍参与关联。旧缓存无需整体失效：暖开清除旧附件关联记录，按链接元数据变化重写受影响分片，不重读未改变的原文。

`node test/run-suite.mjs only link-targets workspace-chrome workspace-media tab-groups index` 验证附件/缺失笔记分流、真实点击、旧缓存兼容与持久化、正文不变，以及明暗模式缝隙像素与顶栏中心线。PDF 页面隐藏通用文档标题行，保留文件工具栏及内置阅读器；普通文档底栏使用纸张底色，外围缝隙与侧栏共用底层。

## 引用事务与完整备份

`reference-path.js` 共用引用范围和路径解析，改写目标保留别名/宽度/锚点/标题，跳过代码；按原库实际目标映射到移动后的路径，包含目录中的笔记自身相对引用。`reference-store.js` 在 `.tracery/operations` 留恢复副本与提交日志，逐笔正文使用版本比较和原子保存。失败回退；进程中止后启动检查未完成事务，外部冲突时不覆盖，保留副本并提示检查。图形旁车与文件同移。当前打开标签、收藏、分组及保存工作区也做路径映射。

事务日志 v2 逐项记录移动意图、完成和回退阶段，原件副本先刷盘；配套文件移动失败时仍能回退已完成项，跳过尚未执行项。启动恢复继续兼容 v1 日志。完整备份校验同时核对空目录清单，并检测复制期间新增或删除的历史/回收站项目。恢复不允许落入内部历史/回收站目录；元数据部分发布后失败或取消时只回收本轮副本，用户文件的未完成目录保留供检查。

普通写入、切库、引用事务和同步共享顺序队列；排队时客户端已断开的请求直接结束，不阻塞后续操作。完整备份仅在扫描及捕获设置时等待当前写入，大文件复制/回读不占住保存队列；源文件/stat/目录清单改变则拒绝提交，避免把混合时点内容冒报为完成快照。

`full-backup.js` 以普通目录和 SHA-256 清单流式处理文件，覆盖当前用户文件、绘图、空目录、历史、回收站、公开界面设置与限定的浏览器会话键。排除凭据/缓存/开发内部路径/草稿，拒绝符号链接和越界条目；20 万文件/目录、32 MiB 清单显式上限。恢复先全量校验，只发布新目录；历史身份只在恢复副本中重绑定，旧版不升级为确定来源。修改时间保留，用户工作区只有点击打开后才应用，可回退本轮存储写入。进度、取消及关闭时收尾不会把 `.incomplete` 报为成功。这里只校验完整性，不对不可信备份做来源认证。

`chrome-tokens.css` 集中标题栏/标签/侧栏/纸张的耦合尺寸、间距和共享底色。`chrome-layout.js` 观察侧栏页签真实高度，换行及换位后重测文档标题的分割线，不移动固定图标行。主题仍定义颜色，移动端保留自己的触屏布局。

新增 `reference-integrity`、`full-backup`、`full-backup-ui`、`chrome-matrix` 四项已加入 `test:ci`。覆盖实际移动/改名/重新关联、同名/编码/目录相对路径、回退/进程中止、34 MiB 附件、二进制/mtime/历史/回收站/会话、新库恢复、篡改/取消/写入失败、备份期间保存队列可用，以及两套主题×明暗×三种桌面宽度、长文宽表图片/PDF和页签换行。使用说明见 [BACKUP.md](BACKUP.md)。
