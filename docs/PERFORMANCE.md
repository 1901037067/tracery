# 大仓库性能

本轮覆盖文件树、启动索引和普通保存。测试使用 10,000 篇生成笔记加一篇入口笔记，分布在 20 个文件夹中，包含正文、标签和双链，全部位于临时目录。

## 本机测量

2026-10-20，Windows / Node / 无头 Edge，同一份仓库，旧实现基线固定为 `4a306b5`：

| 项目 | 优化前 | 优化后 |
|---|---:|---:|
| 首次完整索引 | 约 7.3～9.2 秒 | 约 4.5～5.2 秒 |
| 已有缓存时启动 | 每次重读全部笔记 | 约 1.4～1.6 秒，重读 / 重解析 0 篇 |
| 文件树 DOM | 展开后创建全部行 | 本次桌面视口 32 行，随视口高度变化 |
| 普通保存 | 重建全仓反链，刷新整棵树和图谱 | 仅更新该篇出链与相关反链；不请求树和隐藏图谱 |

时间受机器、磁盘、系统文件缓存及并行任务影响，不作为跨机器硬性门槛；断言检查实际文件数量、读取次数、DOM 数量和数据正确性。每次运行的原始数据在 `dist/performance-preview/metrics.json`。

## 文件树

- 超过 400 个文件时使用虚拟滚动，按展开目录生成行模型，只创建可见行及上下各 8 行缓冲。
- 桌面行高 32px，移动端 40px；窗口变化、侧栏展开时重新计算可视区域。
- 打开笔记只更新选中样式。结构变化保留顶部可见行的位置；折叠、展开、右键菜单、星标、文件定位仍可用。
- 文件是否存在、重名副本避让和标签恢复使用完整文件清单，不使用屏幕中的 DOM 判断。
- 小仓库沿用原有嵌套布局，保持现有间距与交互。

## 索引缓存

- 自动生成 `<仓库>/.tracery/index.json`，保存笔记元数据及搜索所需正文；内容是原笔记的派生副本，随仓库保存在本地，不参与同步与 Git 提交。
- 每次打开仍扫描目录并校验文件大小、mtime 与 ctime；只读取改变或新增的笔记。16 路受限并发避免逐篇 I/O 排队和文件句柄暴增。
- 格式版本、仓库根路径不匹配或缓存损坏时自动重建。缓存不可写时仍能正常使用仓库；原笔记始终是真源。
- 普通编辑立即更新内存索引；缓存写盘防抖 800ms，使用临时文件与原子替换。强制退出导致缓存尚未落盘时，下次会从实际文件重新索引。
- 文件新增 / 删除后重新校验唯一名称解析；目录改名 / 删除、同步写入使用增量扫描，复用未变化内容。扫描完成后一次交换索引，读请求不会看到半棵仓库。
- 调整 Markdown 索引解析规则时，必须递增 `server/index-cache.js` 的缓存版本，避免复用旧解析结果。

## 回归

运行 `npm run test:performance`。脚本只操作专用临时仓库，覆盖缓存损坏 / 旧格式 / 不可写、同尺寸且还原 mtime 的编辑、重复事件、增量反链、重名冲突、目录改名、虚拟滚动末尾打开、屏幕外定位和移动抽屉。浅克隆没有旧提交时跳过旧版计时，其余断言照常执行。

当前仍在内存保留正文以支持全文搜索，内存占用随笔记总大小增长。本轮没有更换完整图谱的力导向算法，也没有实现全文倒排索引；超大图谱和更大规模的全文检索可继续单独优化。
