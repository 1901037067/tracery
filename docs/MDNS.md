# 附近设备发现（mDNS）

mDNS / DNS-SD 让同一局域网里的应用自动公告和查找服务，作用类似附近打印机列表。Tracery 用它列出正在共享的设备和仓库；选择设备后仍须输入主机显示的 6 位通行码。找到设备、配对授权、传输笔记是三个步骤，传输继续复用现有同步引擎。

## 使用

1. 主机在「设置 → 同步」点击「本机当主机，生成通行码」，保持 Tracery 运行。
2. 另一台设备打开「设置 → 同步」，在「附近的共享设备」里选择目标仓库。
3. 输入主机显示的通行码，点「连接所选设备」。首次同步会合并两边的文件。
4. 没看到设备时可点「刷新」、直接输码查找，或使用主机显示的手动地址。

共享只公告当前仓库。停止共享、断开同步、切换仓库都会撤销公告并关闭内嵌服务端。重开设置仍能看到共享状态、通行码和手动地址。同名设备通过仓库名、地址与会话 ID 区分；一个实例同时共享多个仓库尚未实现。

## 范围

- 当前实现使用 IPv4 mDNS 多播 `224.0.0.251:5353`，服务类型 `_tracery-sync._tcp.local`，无需系统安装 Bonjour 服务。
- 公告包含协议版本、随机会话 ID、设备名和仓库名，不包含通行码、token、笔记正文或仓库绝对路径。只有主动开启共享才发布公告。
- 列表按需扫描，退出扫描即释放浏览实例。多个地址并发检查 `/api/health`，确认是可达的 Tracery 服务才显示，不保留跨扫描的陈旧在线状态。
- 网卡地址改变时重新公告。相同设备上可运行多个独立实例，每个共享使用独立的会话名、主机名和随机 TCP 端口。
- 多播受网络设备、防火墙与 Wi-Fi 客户端隔离影响；跨网段、访客 Wi-Fi 或 VPN 不保证自动发现。旧的按码 UDP 查找和手动地址仍可使用，UDP 广播地址按真实子网掩码计算。
- PWA 的扫描由它连接的 Node 服务执行，因此发现的是那台服务所在局域网的设备；手机浏览器自身不直接发送 mDNS。
- 发现到的名称不构成设备身份认证；配对仍走现有通行码 / token 机制。主应用 Web 服务的访问控制、已配对设备撤销和更完善的配对限速可另行完善。

协议依据：[RFC 6762：mDNS](https://www.rfc-editor.org/rfc/rfc6762.html)、[RFC 6763：DNS-SD](https://www.rfc-editor.org/rfc/rfc6763.html)。运行时使用纯 JavaScript 的 [bonjour-service](https://github.com/onlxltd/bonjour-service)。

## 验证与维护

```text
npm run test:mdns
npm run test:lan
npm run test:sync-ui
```

`test:mdns` 使用三个临时 Tracery 实例，关闭旧 UDP 广播，走真实 5353 多播发现、界面选设备、错误码拒绝与真实文件同步；覆盖同名主机、公告内容、共享结束 / 切仓库、手机布局及依赖打包。`test:lan` 禁用 mDNS，验证 UDP 兼容路径独立可用。测试不改真实仓库；截图在 `dist/mdns-preview/`。

本机测试覆盖多进程互发现，不代表已经验证所有实体路由器与不同手机的网络策略。测试隔离开关为 `TRACERY_DISABLE_MDNS=1` 与 `TRACERY_DISABLE_LAN_UDP=1`，正常使用无需设置。

新增运行时依赖后，手工 `repack` 必须带完整传递依赖；`scripts/runtime-deps.mjs` 与 mDNS 测试负责验证这一点，不能只复制 package.json 最上层依赖。
